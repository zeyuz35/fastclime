## 2024-04-12 - Explicit Namespace Calls

**Learning:** S3 method dispatch will successfully automatically route standard base generic function calls (like `plot()`) to the correct methods of an external package (like `igraph`'s `plot.igraph()`), as long as the generic handles dispatch correctly and the external package is properly loaded/installed. This allows shifting dependencies from `Depends` to `Imports`. Explicit namespacing is not required for S3 generic functions (e.g., base R's `plot()`) dispatching to the imported package's methods (e.g., `plot.igraph()`). Method dispatch succeeds automatically as long as the object has the appropriate class. Additionally, when removing packages from Depends, you should be careful to explicitly namespace any functions that were previously provided by that dependency and were implicitly assumed to be available. Furthermore, inline namespacing within the `.R` file (e.g., `utils::flush.console()`) is preferable to modifying the `NAMESPACE` manually to add global `importFrom`s, keeping the code explicitly clear on origin.

**Action:** When removing packages from Depends and adding to Imports, double-check the R code for implicit calls to those packages and update them to use explicit namespacing. Avoid adding `importFrom` for simple single-function utilities if explicit inline namespacing can be done. Use explicit inline namespacing (e.g., `utils::flush.console()`) within the `.R` source files themselves, rather than relying on global `importFrom()` directives in the manually maintained `NAMESPACE` file.
