## 2024-05-24 - Implicit Matrix Conversion Drops Time-Series Attributes in `isSymmetric` and `%*%`

**Learning:** `isSymmetric()` and matrix multiplication (`%*%`) drop or reject time-series class objects like `zoo` and `xts`. Passing a `zoo` or `xts` object directly to `isSymmetric()` throws a `no applicable method` error because they do not have specific S3 methods implemented for `isSymmetric()`, unlike standard matrices. Similarly, while `%*%` will often coerce its inputs to numeric matrices implicitly, the return value and the intermediate structures lose original class and dimension name attributes. In standard time-series handling, explicit coercion to a core matrix using `as.matrix()` is needed *before* calling base functions that expect pure matrices, while safely caching `colnames()` to re-attach to downstream outputs, and ensuring the original input (like `xts` object) is returned to keep data integrity intact.

**Action:** Always capture original object names (`colnames()`) and extract a pure numeric matrix using `as.matrix()` before passing user-provided time-series objects into matrix-exclusive base functions (like `isSymmetric()` or complex linear algebra). Always return the original, unmodified time-series object alongside the results to preserve indices and scaling attributes.
