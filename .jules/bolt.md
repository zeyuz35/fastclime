## 2024-05-15 - Move allocations outside of loop and zero out buffer
**Learning:** Sometimes repeated `CALLOC` and `FREE` within an inner iteration loop like the lambda path iteration in solver algorithms causes overhead and potential for memory leaks (if not carefully freed). Moving the allocation step `CALLOC(buffer)` outside the loop and replacing it with `memset(buffer, 0, N * sizeof(double))` inside the loop not only avoids the leak if a previous version forgot to `FREE`, but also improves memory performance by avoiding repeated system allocations and deallocations.
**Action:** When inspecting inner loops inside solver functions (e.g. `dantzig.c`, `parametric.c`), replace in-loop `CALLOC`/`FREE` pairs with a single `CALLOC` before the loop, a `memset` to zero at the start of the loop, and a single `FREE` after the loop.
