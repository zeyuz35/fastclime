## 2025-03-06 - [DoS Risk in Custom Allocation Macros]
**Vulnerability:** Zero-length array allocations using standard C library functions (`malloc(0)`, `calloc(0)`) inside custom macros (`MALLOC`, `CALLOC`, `REALLOC`) can return `NULL` (implementation-defined), erroneously triggering a fatal `error()` call in the R interpreter (Denial of Service risk).
**Learning:** Returning `NULL` for zero-length allocations breaks the implicit macro guarantee that memory is successfully allocated, leading to crashes or undefined behavior if the pointer is passed to functions expecting non-null pointers (like `memcpy`). Simply checking for `len == 0` and returning `NULL` does not solve this and also introduces double-evaluation hazards in macros.
**Prevention:** Always verify `len > 0` and ensure at least 1 byte/element is allocated (e.g., `malloc((len > 0 ? len : 1) * sizeof(type))`) so that standard library memory functions always receive a non-zero length and return a valid pointer. Also evaluate the macro parameter `len` only once by assigning it to a local variable `size_t _safe_len = (size_t)(len);` to avoid double-evaluation side-effects.
