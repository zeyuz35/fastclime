## 2024-05-18 - Zero-length memory allocation vulnerability in custom memory macros
**Vulnerability:** Custom memory management macros (`MALLOC`, `CALLOC`, `REALLOC`) in `src/myalloc.h` failed to account for zero-length allocation requests, passing a size of 0 to standard C allocation functions (`malloc`, `calloc`, `realloc`). These functions may return `NULL` for zero-length requests, incorrectly triggering the custom error handler (`error()`) designed to catch fatal Out-Of-Memory (OOM) situations.
**Learning:** `malloc(0)`, `calloc(n, 0)`, and `realloc(ptr, 0)` are implementation-defined and can return a null pointer or a valid pointer. Assuming `NULL` means OOM is unsafe unless you verify the length is greater than 0. Furthermore, blindly returning `NULL` for `len == 0` is unsafe if the pointer is later passed to functions that assume non-null pointers like `memcpy`. In macros, we also have double-evaluation hazards so we can't do things like `((len) > 0 ? (len) : 1)`.
**Prevention:** Evaluate the length parameter exactly once into a scoped variable within the macro to avoid double-evaluation hazards (e.g. `size_t _safe_len = (size_t)(len);`). Ensure the allocation length is at least 1 (e.g., `_safe_len = _safe_len > 0 ? _safe_len : 1;`) to guarantee a non-null return on success and reliably differentiate between an OOM error and a zero-length allocation request.
