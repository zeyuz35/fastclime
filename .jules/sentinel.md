## 2024-05-18 - Prevent Zero-Length Memory Allocation Errors
**Vulnerability:** The C memory management macros (`MALLOC`, `CALLOC`, `REALLOC`) passed the `len` parameter directly to `malloc()`, `calloc()`, and `realloc()`. If `len` evaluated to `0`, standard C behavior allows these functions to return `NULL`. This would trigger the macro's error handling condition (`if ((name) == NULL)`), mistakenly causing a fatal R `error()` due to "Memory allocation failed" rather than processing an empty array. Additionally, evaluating the `len` argument multiple times in macro expansion could cause double-evaluation hazards if expressions with side-effects were passed.
**Learning:** Returning `NULL` on a zero-length allocation request can create confusing and application-crashing behaviors (fatal `error()`) instead of safely continuing execution. Standardizing safe lengths and single evaluation using local variables in macros avoids both double-evaluation and erroneous `NULL` error triggers.
**Prevention:** Ensure C macros evaluate arguments strictly once by assigning them to a local typed variable (e.g., `size_t _safe_len = (size_t)(len)`). Also, enforce a minimum allocation size of 1 element (`_safe_len = _safe_len > 0 ? _safe_len : 1;`) so `NULL` is only returned on actual Out-Of-Memory events, and never on legitimate `0`-length requests.
## 2026-05-15 - Prevent 32-bit Integer Overflow in C-Wrapper Allocations
**Vulnerability:** In R functions wrapping C backends, dimension variables like `d` and `nlambda` were passed to `.C()` and their memory calculation sizes (`d * d * nlambda`) could implicitly overflow 32-bit integers if calculated directly within R as `integer`. This causes NAs, silent failures, or corrupted array bounds in the C backend leading to potential memory vulnerabilities.
**Learning:** R's default integer type is 32-bit and maxes out at `.Machine$integer.max` (~2.14 billion). Multiplications of dimensions can easily exceed this limit, producing NA instead of the correct size.
**Prevention:** Explicitly cast array dimension variables to `numeric` (e.g., `as.numeric(d)`) before multiplication to prevent overflow during calculations within R, and explicitly validate sizes against `.Machine$integer.max` before allocating matrices or calling `.C()`.
