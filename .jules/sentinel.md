## 2024-05-02 - Prevent Undefined Behavior and Fatal OOM on Zero-Length Allocations
**Vulnerability:** Zero-length requests passed to standard C allocation functions (`malloc`, `calloc`, `realloc`) might return `NULL`. In the existing custom macros (`MALLOC`, `CALLOC`, `REALLOC`), a `NULL` return triggers a fatal `error("Memory allocation failed")` call, causing an R session crash. Furthermore, returning `NULL` for zero-length arrays and passing it to memory functions like `memcpy` causes Undefined Behavior.
**Learning:** Standard C memory allocation functions are not guaranteed to return a non-NULL pointer for zero-length allocations. The C custom memory management macros didn't account for this, which causes a fatal `error` on success.
**Prevention:** Modified the custom `MALLOC`, `CALLOC`, and `REALLOC` macros to always allocate at least 1 element, even if the requested length is zero (`_safe_len > 0 ? _safe_len : 1`). To prevent double-evaluation hazards of macro arguments, `len` is evaluated once and stored in `size_t _safe_len`.
