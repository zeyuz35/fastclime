## 2024-05-24 - Zero-length memory allocations triggering fatal false OOM and UB
**Vulnerability:** The C extension's custom memory management macros (`MALLOC`, `CALLOC`, `REALLOC`) passed the length parameter directly to standard C allocation functions. Standard `malloc(0)` can return `NULL` according to the C standard, which these macros erroneously interpreted as a fatal Out-Of-Memory error, triggering R's `error()` and crashing the R session. Additionally, directly evaluating the macro argument multiple times creates double-evaluation hazards, and returning `NULL` for `len == 0` risks Undefined Behavior if passed to `memcpy` or similar functions.
**Learning:** In C extensions where memory allocation macros use `NULL` checks to detect fatal memory exhaustion, zero-length allocation requests must be handled explicitly. Because `malloc(0)` is implementation-defined and can legally return `NULL`, it can trigger false positive error conditions.
**Prevention:** Always evaluate macro arguments once using a temporary variable (e.g., `size_t _safe_len = (len)`). Ensure standard C allocation functions are always requested to allocate at least 1 element (e.g., `_safe_len > 0 ? _safe_len : 1`) to guarantee a non-`NULL` valid pointer is returned even for zero-length logical requests, preventing both false OOM errors and potential UB when the pointer is used.
