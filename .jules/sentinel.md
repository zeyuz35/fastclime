## 2024-05-18 - Prevent Zero-Length Memory Allocation Errors
**Vulnerability:** The C memory management macros (`MALLOC`, `CALLOC`, `REALLOC`) passed the `len` parameter directly to `malloc()`, `calloc()`, and `realloc()`. If `len` evaluated to `0`, standard C behavior allows these functions to return `NULL`. This would trigger the macro's error handling condition (`if ((name) == NULL)`), mistakenly causing a fatal R `error()` due to "Memory allocation failed" rather than processing an empty array. Additionally, evaluating the `len` argument multiple times in macro expansion could cause double-evaluation hazards if expressions with side-effects were passed.
**Learning:** Returning `NULL` on a zero-length allocation request can create confusing and application-crashing behaviors (fatal `error()`) instead of safely continuing execution. Standardizing safe lengths and single evaluation using local variables in macros avoids both double-evaluation and erroneous `NULL` error triggers.
**Prevention:** Ensure C macros evaluate arguments strictly once by assigning them to a local typed variable (e.g., `size_t _safe_len = (size_t)(len)`). Also, enforce a minimum allocation size of 1 element (`_safe_len = _safe_len > 0 ? _safe_len : 1;`) so `NULL` is only returned on actual Out-Of-Memory events, and never on legitimate `0`-length requests.
## 2024-05-18 - Fix Integer Overflow Before Memory Allocation
**Vulnerability:** Memory allocation macros (`FC_CALLOC`, `FC_MALLOC`) were invoked using arithmetic expressions that combine signed `int` variables (e.g., `nz + m` or `n + m + 1`). Because the addition is evaluated before being passed to the macro, large matrices could cause the 32-bit `int` addition to overflow into a negative number (Undefined Behavior). This negative number is then implicitly cast to a 64-bit unsigned `size_t` by the macro, resulting in either a failed allocation (`SIZE_MAX` bounds error) or, in worse cases with multiplication, a wrapped small number that bypasses limits and leads to a Heap Buffer Overflow when memory is subsequently accessed.
**Learning:** In C, arithmetic operators like `+` and `*` evaluate using the precision of their operands *before* any assignment or function parameter cast occurs. Passing `nz + m` to a function expecting `size_t` evaluates the addition as signed 32-bit integers, which overflows before the conversion to 64-bit `size_t` can protect it.
**Prevention:** Always explicitly cast at least one operand to `size_t` *before* the arithmetic operation (e.g., `(size_t)nz + m`) when calculating sizes for memory allocations, ensuring the arithmetic is performed safely in 64-bit unsigned space without risk of integer overflow.
