## 2024-05-24 - Zero-Length Allocation Vulnerability in Memory Macros
**Vulnerability:** The custom memory management macros (`MALLOC`, `CALLOC`, `REALLOC`) in `src/myalloc.h` passed the raw length parameter directly to standard C allocation functions (`malloc`, `calloc`, `realloc`). If a length of `0` was requested, the standard allocator could return `NULL`. The macros would misinterpret this `NULL` as an Out-Of-Memory (OOM) condition and call the fatal R `error()` function, leading to unhandled application crashes (Denial of Service). Additionally, the macros evaluated the length parameter multiple times, posing a double-evaluation hazard.
**Learning:** Returning `NULL` for zero-length requests is implementation-defined in C, but in the context of this R package, it caused unexpected application crashes. Furthermore, returning `NULL` for size 0 risks Undefined Behavior if the pointer is later passed to functions expecting non-null pointers like `memcpy`.
**Prevention:** Update memory allocation macros to evaluate the length parameter once (`size_t _safe_len`), and ensure at least 1 element is allocated (e.g., `_safe_len > 0 ? _safe_len : 1`). This guarantees a valid non-null pointer is always returned and prevents accidental OOM crashes or UB.
