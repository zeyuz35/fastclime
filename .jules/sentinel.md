## 2024-03-14 - Zero-length Allocation and Double-Evaluation Vulnerability
**Vulnerability:** The memory allocation macros (`MALLOC`, `CALLOC`, `REALLOC`) passed the `len` parameter directly to standard C allocation functions. This allowed zero-length allocation requests. Depending on the system's C library, `malloc(0)` may return `NULL`, which erroneously triggered the fatal `error()` handler, acting as a potential Denial-of-Service vector. Furthermore, returning `NULL` for size 0 introduces Undefined Behavior if that pointer is later passed to functions like `memcpy`. (Additionally, storing it in a variable prevents any potential double-evaluation hazards if `len` had side effects in other macros).
**Learning:** In C extensions for R, custom memory macros need to strictly enforce minimum allocation lengths (at least 1) to prevent `NULL` returns on zero-length requests.
**Prevention:** Always evaluate macro length parameters into a local variable using a safe, distinct name (e.g., `_myalloc_safe_len`) to avoid variable shadowing in macro expansions. Ensure the allocation size is bounded to at least 1 element (`_myalloc_safe_len > 0 ? _myalloc_safe_len : 1`) to guarantee a non-null valid pointer is returned even for zero logical length requests.
