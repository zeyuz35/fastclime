## 2025-01-31 - [Memory Management Optimization in Solvers]
**Vulnerability:** Memory allocations (`CALLOC`) were present inside tight main loops for mathematical solvers in `dantzig.c` and `parametric.c`. Early `break` conditions within these loops were causing memory leaks when corresponding `FREE` calls were skipped. In long-running processes, this can lead to memory exhaustion and Denial of Service (DoS) vulnerabilities.
**Learning:** Frequent heap allocations within hot loops not only impact performance but also introduce higher risks of memory leaks if all exit paths (like early `break` statements) aren't flawlessly covered with deallocations.
**Prevention:** Avoid dynamic memory allocations within tight mathematical solver loops altogether. A robust pattern for this codebase is to hoist the `MALLOC` call outside the loop, use `memset` to zero-initialize the buffer at the start of each iteration, and guarantee a single `FREE` statement at the very end of the function scope.
